# LZ76 definition and independent verification

## Sources and chosen convention

- A. Lempel and J. Ziv (1976), *On the Complexity of Finite Sequences*, IEEE
  Transactions on Information Theory 22(1), 75–81.
  [DOI](https://doi.org/10.1109/TIT.1976.1055501). Original sequence-complexity
  definition; the exhaustive history realizes the minimum production count.
- B. I. Mills (2003), *Entropies Defined by Parsing Algorithms*, Research Letters
  in the Information and Mathematical Sciences 5, 17–22, section 2.
  [University-hosted paper](https://mro.massey.ac.nz/bitstreams/1ecf0b74-226c-4826-b381-18413c506f64/download).
  Explicit reproduction/production definitions and the worked parsing
  `1 | 0 | 11 | 010 | 11` for `101101011`, giving five components.
- E. Estevez-Rams, R. Lora Serrano, B. Aragón Fernández, and I. Brito Reyes (2013),
  *On the non-randomness of maximum Lempel Ziv complexity sequences of finite size*,
  Chaos 23, 023118. [DOI](https://doi.org/10.1063/1.4808251),
  [author manuscript](https://arxiv.org/abs/1311.0546), section II.
  Gives `0 | 1 | 00 | 11 | 101 | 101100` for `010011101101100` (six components)
  and explains the limitations of finite-count randomness interpretations.

The [metric guide](../complexity/lz76.md) specifies exhaustive parsing, overlapping
reproduction from any earlier starting position, and a final nonempty suffix
counted even if reproducible. There is no added end marker. Empty input extends
the convention with zero phrases; a single byte gives one. Primitive production
histories, LZ77, LZ78, normalization, and entropy-rate estimators are outside this API.

The original publisher page was not readable through the research browser;
implementation details were checked against the accessible Mills exposition
and Estevez-Rams et al. manuscript, rather than inferred from a software package.
No third-party implementation was copied into the library.

## Independent checks

```sh
python3 scripts/reference_lz76.py --check
cargo test --locked --test lz76
cargo run --locked --example lz76
```

The Python generator grows a candidate until it is absent from the input prefix
ending just before the candidate's last byte. This substring-novelty approach
is separate from the Rust scan for the longest match over earlier source starts.
It retains phrase boundaries as well as counts. **1,035 fixtures** cover every
binary sequence through length nine (1,023), plus twelve hand/published examples,
arbitrary bytes, all byte labels, repeated alphabets, UTF-8 bytes, and a long
constant. Both published parses above are asserted independently in the generator.
Rust checks counts and the count at every retained phrase boundary.

A second Rust oracle minimizes over **all valid production histories** using
dynamic programming. For each endpoint `e`, it tries each start `p<e` and tests
whether `x[p..e-1]` can be copied from a start before `p`, then adds the final byte.
The recurrence is `D[e]=min(D[p]+1)` over valid productions, with `D[0]=0`.
Copyability is checked by substring search in `x[..e-2]`; the empty copied prefix
is always valid. This is not the production algorithm's greedy recurrence.
It checks all 2,047 binary strings through length ten and all their prefixes,
plus fixed-seed byte properties. Other properties check bijective renaming,
finite bounds, constant/all-distinct samples, and one-symbol extension bounds.
Reversal is deliberately not assumed: `AAB` has two phrases and `BAA` has three.

The [fuzz target](../fuzzing.md) uses independent substring novelty on up to 128
bytes, exact count equality, and invariants. All verification is integer-exact;
there is no numerical tolerance. The standalone allocation test and memory probe
check the no-heap contract. Benchmarks bound diverse inputs because the scalar
algorithm can take quadratic time. No defect was found during this increment's
initial exact-reference checks; no artificial regression case is claimed.
