# Celandine project instructions

- Read `finite_sequence_information_complexity_project_plan.md` completely before
  making changes; it is the authoritative project specification.
- Follow `CONTRIBUTING.md`. The user has adopted its automated tests, runnable
  examples, independent verification, regression tests, and measured performance
  workflow for ongoing development until they explicitly change it.
- Keep examples usable as new functionality is added. Run changed examples and
  the relevant validation checks, and report their results.
- For every public concept, maintain short, precise explanations of what it is,
  why it matters, its formula/operation with terms and units explained, and a
  worked example. Include cited historical context for named metrics/algorithms.
  Follow the educational documentation standard in `CONTRIBUTING.md`; keep the
  README overview, API docs, and runnable example introductions in sync.
- Stay within the user's authorized milestone. Do not implement later roadmap
  metrics, a CLI, or application layers without a corresponding request.
